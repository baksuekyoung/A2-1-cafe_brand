# 브랜드 아이덴티티 생성기

> **AI 활용 텀프로 1조** · [Project A] 브랜드 아이덴티티 생성기
> 주제 **카페** · 팀장 **박수경** · 기한 **2026-08-27**

브랜드 브리프(업종·타깃·키워드)를 넣으면 **이름·슬로건·스토리·컬러 팔레트·로고 시안**까지
한 번에 만들어 문서로 남기는 파이썬 프로그램입니다.

```
[1] 브리프  →  [2] 네이밍·슬로건·스토리  →  [3] 컬러 팔레트  →  [4] 로고 시안
                                                                      ↓
                                              [5] 결과 저장 & 에러 처리 통합
                                                                      ↓
        brand_result.md · brand_result.json · brand_tokens.css · logo_01.png · run_report.md
```

## 팀 구성

| 단계 | 담당 | 파일 | 상태 |
| --- | --- | --- | :---: |
| 진행 총괄 | **박수경** | 주제·브리프 확정, 최종 취합 | 진행 중 |
| [1] 브리프 · 입력 | **김준오** · 이태우 | `step1_brief.py` | 규격 제출 |
| [2] 네이밍 · 슬로건 · 스토리 | **박연수** | `step2_naming.py` | 규격 제출 · **연결 완료** |
| [3] 컬러 팔레트 | **박수경** | `step3_palette.py` | 작업 예정 |
| [4] 로고 시안 | **이예은** | `step4_logo.py` | 작업 예정 |
| [5] 결과 저장 · 에러 처리 통합 | **노희선** | `main.py` · `brand_result/` | **완료** |

각 단계의 입출력 규격은 담당자가 정하고, [5]가 그대로 받아 맞춥니다.
[1]은 김준오님, [2]는 박연수님이 정한 규격을 씁니다.

## 바로 실행

```bash
python main.py
```

Python 3.10 이상. **[5]는 외부 패키지 없이 표준 라이브러리만** 씁니다.
[2]에서 LLM을 부르려면 `pip install openai python-dotenv` 후
`.env` 에 `OPENAI_API_KEY` 를 넣으시면 됩니다. **없어도 예시 값으로 돌아갑니다.**

## 팀원분들께 — 이것부터 봐 주세요

📄 **[`docs/데이터-계약.md`](docs/데이터-계약.md)**

주제는 **카페**로 정해졌습니다. 바로 쓸 수 있는 브리프를
[`samples/brief.json`](samples/brief.json) 에 넣어 뒀습니다 — 계약 검증을 통과하는 값이니
내용만 팀 의견에 맞게 고쳐 쓰시면 됩니다.

각 단계가 **무슨 형식으로** 결과를 넘길지 정해 둔 문서입니다.
**코딩을 시작하기 전에** 이것만 맞춰 주시면 통합은 제가 합니다.
서로의 코드를 읽을 필요가 없습니다.

| 단계 | 만들 파일 | 함수 |
| --- | --- | --- |
| [1] 브리프 | `step1_brief.py` | `load_brief() -> dict` |
| [2] 네이밍·슬로건·스토리 | `step2_naming.py` | `generate_naming(brief) -> dict` |
| [3] 컬러 팔레트 | `step3_palette.py` | `generate_palette(brief, naming) -> dict` |
| [4] 로고 시안 | `step4_logo.py` | `generate_logos(brief, naming, palette) -> list` |

**파일 하나, 함수 하나면 됩니다.** 안에서 어떤 라이브러리를 쓰든, 함수를 몇 개로 쪼개든 자유입니다.

## 왜 계약을 먼저 정했나

박연수님이 이렇게 적으셨습니다.

> "이전 텀프로때 제가 최종 MD파일 작성을 맡았었는데 ... **설계한 분의 작업물이랑 맞지가 않다보니 파일 정리에 좀 시간이 걸렸어서**"

이건 사람 문제가 아니라 **순서 문제**입니다. 각자 코드를 먼저 쓰고 마지막에 합치면,
합치는 사람이 남의 코드 넷을 읽어서 형식을 맞춰야 합니다.

게다가 이번엔 **대면으로 모일 수가 없습니다.**

| | |
| --- | --- |
| 과제 기한 | **8/27** |
| 노희선 대면 가능 | 8/29 부터 |
| 박연수 | 서울 출장 8/24~28 |

기한이 지난 뒤에야 대면이 됩니다. **문서로 규격을 맞추는 것 말고 방법이 없습니다.**

## 만들어지는 것

| 파일 | 내용 |
| --- | --- |
| `brand_result.json` | 텍스트 결과 전체 |
| **`brand_result.md`** | **사람이 읽는 결과 문서** |
| `run_report.md` | 어느 단계가 되고 안 됐는지 |
| `brand_tokens.css` | 팔레트를 CSS 변수·Tailwind 설정으로 |
| `logo_01.png` … | 로고 시안 |

### `brand_result.md` 가 제일 중요합니다

> **평가는 코드와 마크다운(.md) 문서만 봅니다.**

JSON 만 남기면 평가자가 결과를 볼 방법이 없습니다. 터미널 출력도 마찬가지입니다.

## 이 파트가 지키는 약속

**무슨 일이 있어도 결과를 남깁니다.**

| 상황 | 어떻게 되나 |
| --- | --- |
| 파트가 하나도 없음 | 빈 자리를 표시하고 저장 |
| 팀원 코드가 예외를 던짐 | 그 단계만 실패로 기록, 뒤 단계는 계속 |
| 파일은 있는데 함수명이 다름 | 계약 문서를 가리키며 알림 |
| 필요한 패키지를 안 깜 | **"파일이 없다"와 구분해서** 알림 |
| 규격이 어긋남 | **버리지 않고** 저장 + 어긋난 곳 기록 |
| 로고 한 장이 깨짐 | 나머지 장은 저장 |
| 저장이 전부 실패 | 종료 코드 `1` 로 알림 (조용히 성공하지 않음) |

마지막 줄이 중요합니다. 조용히 `0` 을 돌려주면 자동화가 성공으로 오해합니다.

### 규격은 부탁만 하지 않고 셉니다

계약에 "스토리 200자 이상" 이라고 적어도 실제로는 짧게 옵니다.
그래서 받은 뒤에 **세어 보고** 어긋나면 `run_report.md` 에 적습니다.

버리지는 않습니다. **사람이 보고 판단할 문제**이기 때문입니다.

## 테스트

```bash
python -m pytest -q
```

33개. 전부 **실패 상황**을 시험합니다 — 파트가 없을 때, 남의 코드가 터질 때,
규격이 어긋날 때, 저장이 안 될 때.

> 테스트를 쓰다가 제 코드의 버그를 하나 잡았습니다.
> 팀원 파일 **안에서** 나는 `ModuleNotFoundError` 를 "파일이 없습니다" 로 잘못 알리고 있었습니다.
> 그러면 팀원은 멀쩡한 파일을 다시 만들려고 합니다.
> 지금은 `없는 모듈: requests` 처럼 구분해서 알립니다.

## 구조

```
main.py                    통합 실행 — 있는 파트만 모아 결과를 낸다
brand_result/
  runner.py                [1]~[4] 호출과 에러 처리 ← 이 파트의 핵심
  validate.py              계약대로 왔는지 검사 (막지 않고 기록만)
  store.py                 파일 저장 + 명도 대비 계산
  report.py                brand_result.md · run_report.md 생성
docs/
  데이터-계약.md            ← 팀원분들이 볼 문서
tests/                     33개, 전부 실패 상황
```

Python 3.10 이상. **외부 패키지가 필요 없습니다** — 표준 라이브러리만 씁니다.
1~4단계에서 어떤 라이브러리를 쓰시든 통합은 영향받지 않습니다.
