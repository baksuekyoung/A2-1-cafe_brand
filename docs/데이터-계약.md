# 단계 간 데이터 계약

> 1~4단계가 결과를 **어떤 형식으로** 넘길지 규정한 문서입니다.
> 구현을 시작하기 전에 형식을 먼저 확정해, 통합 시점의 형식 불일치를 없애는 것이 목적입니다.
>
> **형식만 지키면 내부 구현은 자유입니다.** 사용 라이브러리와 함수 분할 방식은 제약하지 않습니다.

---

## 전체 흐름

```
[1] 브랜드 브리프        →  brief      (dict)
[2] 네이밍·슬로건·스토리  →  naming     (dict)
[3] 컬러 팔레트          →  palette    (dict)
[4] 로고 시안            →  logos      (list)
                              ↓
[5] 결과 저장 & 에러 처리 통합
     brand_result.json / brand_result.md / brand_tokens.css / logo_01.png / run_report.md
```

---

## [1] 브랜드 브리프 — `brief`


```python
{
  "industry": "카페",                                    # 업종
  "target": "20~30대 직장인, 일상 속 여유를 찾는 사람",     # 타깃
  "keywords": ["여유", "따뜻함", "일상의 쉼표", "감성"],    # 핵심 키워드
  "tone": "따뜻하고 감성적이며 과하지 않게 세련된 분위기",   # 톤앤매너
  "competitors": ["블루보틀", "스타벅스"],                 # 경쟁사
  "notes": "한글과 영어로 모두 활용하기 쉬운 브랜드명을 원함" # 추가 요청
}
```

| 키 | 타입 | 필수 | 비고 |
| --- | --- | :---: | --- |
| `industry` | str | ✅ | 빈 문자열 불가 |
| `target` | str | ✅ | 빈 문자열 불가 |
| `keywords` | list[str] | ✅ | **2개 이상** |
| `tone` | str | — | [1] 에서 기본값을 채워 넘깁니다 |
| `competitors` | list[str] | — | 〃 |
| `notes` | str | — | 〃 |

실행 가능한 예시 값은 [`samples/brief.json`](../samples/brief.json) 에 있습니다.

**[1] 단계 내부에서 검증하는 항목** (따라서 [5]에 도달하면 이미 걸러진 상태입니다)
파일 없음 · `.json` 아님 · JSON 문법 오류 · 필수 필드 누락 · 자료형 불일치 ·
빈 문자열 · 출력 폴더 생성 실패 · `.env` 에 API 키 없음

**[5]는 같은 것을 한 번 더 봅니다.** 중복이 아니라 안전망입니다 —
[1]을 건너뛰고 파일을 직접 넣어 돌리는 경우에도 규격이 지켜지는지 확인해야 하고,
어긋난 항목은 `run_report.md` 에 남깁니다.

## [2] 네이밍 · 슬로건 · 스토리 — `naming`



```python
{
  "naming": [
    {"name": "쉼표", "english": "Comma", "reading": "COM-ma",
     "meaning": "문장을 잠시 멈추는 기호에서 따왔습니다"},
    {"name": "여백", "english": "Yeobaek", "reading": "YEO-baek",
     "meaning": "비어 있음이 곧 쉼이라는 뜻입니다"},
    {"name": "모닥", "english": "Modak", "reading": "MO-dak",
     "meaning": "작지만 확실한 따뜻함을 주는 공간입니다"}
  ],
  "slogans": [
    "잠깐 멈추셔도 됩니다",
    "혼자여도 괜찮은 자리",
    "하루에 한 번, 쉼표"
  ],
  "story": "오피스 상권의 점심시간은 늘 붐빕니다. ...",   # 300자 내외

  # 보너스 — 없어도 규격 미달이 아닙니다
  "competitors": [
    {"competitor": "블루보틀",
     "position": "커피 자체에 집중하게 하는 스페셜티 브랜드입니다",
     "differentiation": "우리는 '앉아 있어도 되는 시간'을 팝니다"}
  ]
}
```

| 키 | 타입 | 필수 | 비고 |
| --- | --- | :---: | --- |
| `naming` | list[dict] | ✅ | **3~5개**, 각 항목에 `name`·`meaning` |
| ↳ `english` | str | ✅ | **보너스(다국어 네이밍)** — 같은 이름의 영문 표기. 알파벳 12자 안쪽 |
| ↳ `reading` | str | — | 영문 표기를 읽는 법 (예: `OWN-gee`) |
| `slogans` | list[str] | ✅ | **3개** — 명세가 요구하는 개수입니다 |
| `story` | str | ✅ | **300자 내외** (탄생 배경·철학·비전) |
| `competitors` | list[dict] | — | **보너스** — 경쟁사별 차별화 포인트 |

**보너스로 "다국어 네이밍 지원" 을 택했습니다.**
그래서 `english` 는 채워져 있어야 하고, 비면 `run_report.md` 에 기록됩니다.
결과 문서에는 `쉼표 (Comma, COM-ma)` 형태로 실립니다.

`competitors` 는 선택입니다. 있으면 차별화 표가 함께 실리고, 없어도 규격 미달이 아닙니다.

> **`naming[0]` 이 대표 이름으로 사용됩니다.** 우선순위가 높은 안을 맨 앞에 둡니다.

**슬로건은 문자열 배열입니다.** 하나짜리 문자열이 아니라 세 개가 담긴 리스트입니다.
명세가 3개를 요구하는데 하나만 오면 그 자리에서 규격 미달이 됩니다.

## [3] 컬러 팔레트 — `palette`


```python
{
  "main": {"hex": "#2F4858", "name": "딥 네이비", "reason": "차분함을 위해 채도를 낮췄습니다"},
  "subs": [
    {"hex": "#F6F4F1", "name": "웜 화이트", "reason": "여백을 만듭니다"},
    {"hex": "#C9A227", "name": "머스터드",   "reason": "포인트 색입니다"}
  ]
}
```

| 키 | 타입 | 필수 | 비고 |
| --- | --- | :---: | --- |
| `main` | dict | ✅ | `hex`·`name`·`reason` |
| `subs` | list[dict] | ✅ | **2개 이상**, 같은 구조 |

### HEX 형식

`#` 을 붙인 **6자리 대문자**로 표기합니다 — `#2F4858` ⭕ / `2f4858` ❌ / `rgb(47,72,88)` ❌

5단계가 이 값으로 **명도 대비를 계산**하고 CSS 변수를 만듭니다. 형식이 다르면 계산이 안 됩니다.
(대비가 4.5:1 미만이면 저장은 하되 `run_report.md` 에 경고를 남깁니다. 웹 접근성 기준입니다.)

## [4] 로고 시안 — `logos`


```python
[
  {"image_bytes": b"\x89PNG...", "prompt": "A minimal comma-shaped logo mark, ..."},
  {"image_bytes": b"\x89PNG...", "prompt": "..."}
]
```

| 키 | 타입 | 필수 | 비고 |
| --- | --- | :---: | --- |
| `image_bytes` | bytes | ✅ | PNG **원본 바이트** |
| `prompt` | str | ✅ | 이미지 생성에 쓴 영어 프롬프트 |

`image_bytes` 대신 **이미 저장한 파일 경로**를 주셔도 됩니다.

```python
[{"path": "output/logo_raw_01.png", "prompt": "..."}]
```

둘 중 하나만 있으면 됩니다. `image_bytes` 가 있으면 그걸 먼저 씁니다.

> **프롬프트는 영어로 작성합니다.** 한국어 주제를 이미지 API 에 그대로 넘기면
> 엉뚱한 그림이 나옵니다 (이전 과제에서 "20-30대 여성"을 인물 사진 요청으로 읽어 사람 사진이 나왔습니다).
> 그 영어 프롬프트를 `prompt` 에 그대로 담아 주시면 결과 문서에 근거로 남습니다.

## [5] 결과 저장 & 에러 처리 통합


위 네 가지를 받아 아래를 만듭니다.

| 파일 | 내용 |
| --- | --- |
| `brand_result.json` | 텍스트 결과 전체 |
| `brand_result.md` | **사람이 읽는 결과 문서** |
| `brand_tokens.css` | 팔레트를 CSS 변수·Tailwind 설정으로 |
| `logo_01.png` … | 로고 시안 |
| `run_report.md` | 어느 단계가 성공/실패했는지 |

### `brand_result.md` 가 제일 중요합니다

> **평가는 코드와 마크다운(.md) 문서만 봅니다.**

JSON 만 남기면 평가자가 결과를 볼 방법이 없습니다. 터미널 출력도 마찬가지입니다.
**반드시 `.md` 로 남겨서 커밋해야 합니다.**

---

## 한 단계가 실패해도 멈추지 않습니다

5단계는 **부분 실패를 허용**합니다.

- 2단계가 실패해도 3·4단계 결과는 저장됩니다
- 이미지 API 가 막혀도 텍스트 결과는 남습니다
- 무엇이 왜 실패했는지는 `run_report.md` 에 적힙니다

그래서 **각자 파트가 아직 안 끝나도 통합을 돌려볼 수 있습니다.** 빈 자리는 빈 자리로 표시됩니다.
막판에 한 번에 합치지 말고, 되는 데까지 자주 돌려 보세요.

## 넘겨주실 때

각 단계는 아래 형태의 **함수 하나**로 구현합니다.

```python
# naming.py
def generate_naming(brief: dict) -> dict:
    """위 [2] 규격의 dict 를 돌려준다."""
    ...
```

| 단계 | 파일명 | 함수명 |
| --- | --- | --- |
| [1] | `brief.py` | `load_brief() -> dict` |
| [2] | `naming.py` | `generate_naming(brief) -> dict` |
| [3] | `palette.py` | `generate_palette(brief, naming) -> dict` |
| [4] | `logo.py` | `generate_logos(brief, naming, palette) -> list` |

통합 실행기는 이 이름으로 각 단계를 호출합니다. **단계당 파일 하나, 함수 하나입니다.**
