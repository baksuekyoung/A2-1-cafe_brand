## 4. 기능 요구 사항

### 1. 사용자 입력

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| `print` 와 `input` 으로 대화형 입력 | ✅ | `main.ask_brief` / `main.ask_output` |
| 필수 입력: 브리프 파일 경로 | ✅ | 올바른 파일이 올 때까지 다시 묻습니다 |
| 선택 입력: 출력 폴더 (기본값 `./output`) | ✅ | 엔터를 치면 기본값 |

### 2. 브랜드 브리프 입력

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| JSON 파일로 입력 | ✅ | 경로·확장자·문법을 각각 구분해 안내. 읽고 검증하는 곳은 `main.load_brief` 하나뿐입니다 |
| 필수: `industry` `target` `keywords` | ✅ | 없는 필드를 이름으로 알려 줍니다 |
| 선택: `tone` `competitors` `notes` | ✅ | 기본값을 채워 다음 단계로 넘깁니다 |

JSON 문법 오류는 **몇 번째 줄인지** 알려 줍니다. 줄 번호가 없으면 고칠 수가 없습니다.

### 3~5. 네이밍 · 슬로건 · 스토리

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| LLM API 로 브랜드명 후보 3~5개 | ✅ | 프롬프트가 **4개 이상**을 요구합니다. 업종어(`○○카페`)와 브리프 키워드 복붙을 막고, 후보마다 다른 유형을 요구합니다 |
| 어느 LLM 을 쓰는가 | — | **코디세이 공개 API** → OpenAI → Gemini 순으로 시도합니다 |
| 각 네이밍의 의미/유래 설명 | ✅ | `meaning` 필드 |
| 슬로건 3개, 톤앤매너 반영 | ✅ | 상황·감각·브랜드명으로 겨냥을 나눕니다 |
| 스토리 300자 내외 | ✅ | 280자에 못 미치면 다시 청합니다(최대 2회). 그래도 짧으면 `run_report.md` 에 기록 |
| 탄생 배경·철학·비전 포함 | ✅ | `STORY_RULE` 에 3단 구조로 명시 |

### 6. 컬러 팔레트

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| LLM API 로 컬러 추천 | ✅ | `palette.py` — [2] 가 정한 브랜드명·스토리를 프롬프트에 넣어 글과 색이 따로 놀지 않게 합니다 |
| 메인 1개 + 서브 2~3개를 HEX 로 | ✅ | `#RRGGBB` 형식을 검사합니다. 메인이 흰 배경에 묻히면 다시 청합니다 |
| **matplotlib 등으로 팔레트 PNG 저장** | ✅ | matplotlib 이 있으면 이름까지, 없으면 표준 라이브러리로 |

`matplotlib` 이 없는 환경에서도 PNG 가 나옵니다. `zlib` 과 `struct` 로 직접 인코딩하고,
HEX 코드는 5×7 비트맵 글꼴로 찍습니다. [5] 는 외부 패키지 없이 돌아가는 것이 약속입니다.

추가로 `brand_tokens.css` (CSS 변수·Tailwind 설정)와, 각 색의 **본문 대비 명도비**를
`brand_result.md` 에 함께 냅니다.

### 7. 로고 시안

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 이미지 생성 API 로 로고 2~3개 | ✅ | 기본 2장, `--logos 3` 으로 3장. 시안마다 다른 템플릿 |
| 어느 이미지 API 를 쓰는가 | — | **코디세이** → OpenAI → Gemini → Pollinations |
| PNG 파일로 저장 | ✅ | JPEG 로 오면 PNG 로 변환합니다 (확장자만 바꾸지 않습니다) |

**프롬프트에 한국어를 넣지 않습니다.** 한국어 브리프를 그대로 넘기면
`"20-30대 직장인"` 을 인물 사진 요청으로 읽어 로고 자리에 사람 얼굴이 나옵니다.
[`brand_result/logo_prompt.py`](../brand_result/logo_prompt.py) 가 영어로 옮긴 뒤 넘깁니다.

쓴 프롬프트는 `logo_prompts.md` 로 남깁니다. **이미지 생성이 실패하거나 결과가
마음에 들지 않아도 이 파일만 있으면 사람이 직접 만들 수 있습니다.**

이 문서에는 프롬프트가 **두 벌** 실립니다.

| | 쓰는 곳 | 형식 |
| --- | --- | --- |
| 직접 만들 때 | ChatGPT · Copilot 등 대화형 도구 | 온전한 문장, **브랜드 이름 없음** |
| 프로그램이 쓴 것 | 이미지 생성 API | 쉼표 나열식 |

대화형 도구에 API 용 프롬프트를 넣으면 그림이 안 나옵니다.
`logo for a brand called ...` 는 상표 정책에 걸려 거절당하고,
쉼표로 나열한 낱말 뭉치는 지시문으로 읽혀 되묻기만 합니다.

**평가가 코드와 마크다운만 보므로**, JSON 만 남기면 결과를 읽어 줄 사람이 없습니다.

### 9. 에러 처리

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 실패 시 에러를 출력하고 다음 단계 진행 | ✅ | `runner.run_step` 이 단계별로 예외를 가둡니다. 저장도 파일 단위로 가둡니다 |
| 키가 없거나 잘못되면 명확한 안내 | ✅ | `test_api.py` · 키가 거부되면(401·403) 그 사실을 알립니다 |

한 단계가 무너져도 진행된 만큼을 저장하고, 실패 원인을 `run_report.md` 에 남깁니다.
**예시 값으로 대체된 자리도 그 문서에 적힙니다** — 받는 사람이 실제 생성 결과로 착각하면 안 됩니다.
저장을 한 건도 못 하면 종료 코드 `1` 을 돌려줍니다 — 조용히 성공한 척하지 않습니다.

## 5. 보너스 과제 (선택)

명세는 두 가지 중 선택입니다. **1번 "경쟁사 분석" 을 택했습니다.**
> *"입력된 경쟁사 브랜드를 분석하여 차별화 포인트를 제안한다"*

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| **1번 · 경쟁사 분석 → 차별화 포인트 제안** | ✅ **← 택한 것** | 경쟁사마다 `competitor`·`position`·`differentiation` |
| 2번 · 한글 + 영문 네이밍 동시 생성 | ✅ 덤으로 구현 | 택하지 않았지만 동작합니다 |

### 경쟁사 분석을 어떻게 만드는가

프롬프트(`COMPETITOR_RULE`)가 경쟁사마다 세 가지를 요구합니다.

| 필드 | 무엇 |
| --- | --- |
| `competitor` | 경쟁사 이름 |
| `position` | 그 브랜드가 시장에서 차지한 자리를 한 문장으로 |
| `differentiation` | 우리가 다르게 갈 지점을 한 문장으로 |

**막연한 말 대신 이 브리프의 타깃·키워드에 근거해** 쓰라고 못 박습니다.
경쟁사를 나열만 하면 분석이 아니기 때문입니다.

셋 다 채워진 항목만 남깁니다(`_normalize`). 브리프에 경쟁사가 없으면 빈 배열이고,
선택 필드이므로 규격 위반이 아닙니다.

결과 문서에는 표로 실립니다.

| 경쟁사 | 시장에서의 자리 | 우리가 다르게 갈 지점 |
| --- | --- | --- |
| 블루보틀 | 미니멀리즘과 스페셜티 커피의 전문성… | 전문가적인 시선보다 정서적 휴식에 집중… |

---

### 덤 — 다국어 네이밍을 어떻게 만드는가

프롬프트(`MULTILINGUAL_RULE`)가 영문 표기의 조건을 못 박습니다.

- 소리 나는 대로 옮기거나(온기 → Ongi), 뜻이 통하는 영어 낱말로(쉼표 → Comma)
- **간판·도메인·SNS 계정에 그대로 쓸 수 있어야** 하므로 알파벳만, 12자 안쪽
- 영어권 사람이 발음하기 쉬울 것, 다른 뜻으로 읽히지 않을 것
- 후보끼리 영문 표기가 겹치지 않을 것

`reading` 에 읽는 법(`OWN-gee`)을 함께 받습니다. 한국어 사용자가 영문 표기를
어떻게 소리 내는지 알려 주는 자리입니다.

**읽는 법이 영문 표기를 그대로 베끼면 잡습니다.** 실측으로 `NOOK / NOOK` 이 나온 적이
있는데, 그러면 아무것도 알려 주지 못합니다. 음절을 하이픈으로 나누게 했습니다.

**셋 다 검증합니다.**

| 검사 | 걸리는 경우 |
| --- | --- |
| `english` 가 비었는가 | 빈 문자열 |
| `english` 가 알파벳인가 | 한글이 섞임 |
| `reading` 이 비었는가 | 빈 문자열 |
| `reading` 이 알파벳인가 | 한글이 섞임 |
| `reading` 이 `english` 와 다른가 | 그대로 베낌 |

어긋나면 `run_report.md` 에 기록됩니다. 버리지는 않습니다 — 사람이 보고 판단할 문제입니다.

결과 문서에는 `쉼표 (Comma, COM-ma)` 형태로 실립니다.

## 테스트

```bash
python -m pytest -q
```

**192개.** 전부 실패 상황을 검증합니다 — 단계 파일이 없을 때, 외부 코드가 예외를 던질 때,
규격이 어긋날 때, 저장이 불가능할 때, 브리프 입력이 잘못됐을 때,
**로고 프롬프트에 한국어가 섞였을 때**, 보너스 항목의 모양이 어긋났을 때,
**LLM 이 hex 를 소문자나 `rgb()` 로 줬을 때**.

테스트는 실제 API 를 부르지 않습니다. `conftest.py` 가 키를 지우고 네트워크를 막습니다 —
막지 않으면 "키가 없을 때" 를 시험하려던 테스트가 남아 있는 다른 키를 주워 실제로 호출합니다.
