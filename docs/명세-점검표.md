## 4. 기능 요구 사항

### 1. 사용자 입력

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| `print` 와 `input` 으로 대화형 입력 | ✅ | `main.ask_brief` / `main.ask_output` |
| 필수 입력: 브리프 파일 경로 | ✅ | 올바른 파일이 올 때까지 다시 묻습니다 |
| 선택 입력: 출력 폴더 (기본값 `./output`) | ✅ | 엔터를 치면 기본값 |

### 2. 브랜드 브리프 입력

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| JSON 파일로 입력 | ✅ | 경로·확장자·문법을 각각 구분해 안내 |
| 필수: `industry` `target` `keywords` | ✅ | 없는 필드를 이름으로 알려 줍니다 |
| 선택: `tone` `competitors` `notes` | ✅ | 기본값을 채워 다음 단계로 넘깁니다 |

JSON 문법 오류는 **몇 번째 줄인지** 알려 줍니다. 줄 번호가 없으면 고칠 수가 없습니다.

### 3~5. 네이밍 · 슬로건 · 스토리

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| LLM API 로 브랜드명 후보 3~5개 | ✅ | OpenAI / Gemini 중 있는 키로 호출 |
| 각 네이밍의 의미/유래 설명 | ✅ | `meaning` 필드 |
| 슬로건 3개, 톤앤매너 반영 | ✅ | 상황·감각·브랜드명으로 겨냥을 나눕니다 |
| 스토리 300자 내외 | ✅ | 길이를 세어 어긋나면 `run_report.md` 에 기록 |
| 탄생 배경·철학·비전 포함 | ✅ | `STORY_RULE` 에 3단 구조로 명시 |

### 6. 컬러 팔레트

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| LLM API 로 컬러 추천 | ✅ | `step3_palette.py` |
| 메인 1개 + 서브 2~3개를 HEX 로 | ✅ | `#RRGGBB` 형식을 검사합니다 |
| **matplotlib 등으로 팔레트 PNG 저장** | ✅ | matplotlib 이 있으면 이름까지, 없으면 표준 라이브러리로 |

`matplotlib` 이 없는 환경에서도 PNG 가 나옵니다. `zlib` 과 `struct` 로 직접 인코딩하고,
HEX 코드는 5×7 비트맵 글꼴로 찍습니다. [5] 는 외부 패키지 없이 돌아가는 것이 약속입니다.

추가로 `brand_tokens.css` (CSS 변수·Tailwind 설정)와, 각 색의 **본문 대비 명도비**를
`brand_result.md` 에 함께 냅니다.

### 7. 로고 시안

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 이미지 생성 API 로 로고 2~3개 | ✅ | OpenAI → Gemini → Pollinations 순으로 시도 |
| PNG 파일로 저장 | ✅ | JPEG 로 오면 PNG 로 변환합니다 (확장자만 바꾸지 않습니다) |

**프롬프트에 한국어를 넣지 않습니다.** 한국어 브리프를 그대로 넘기면
`"20-30대 직장인"` 을 인물 사진 요청으로 읽어 로고 자리에 사람 얼굴이 나옵니다.
[`brand_result/logo_prompt.py`](../brand_result/logo_prompt.py) 가 영어로 옮긴 뒤 넘깁니다.

쓴 프롬프트는 `logo_prompts.md` 로 남깁니다. **이미지 생성이 실패하거나 결과가
마음에 들지 않아도 이 파일만 있으면 사람이 직접 만들 수 있습니다.**

이 문서에는 프롬프트가 **두 벌** 실립니다.

| | 쓰는 곳 | 형식 |
| --- | --- | --- |
| 직접 만들 때 | ChatGPT · Copilot 등 대화형 도구 | 온전한 문장, **브랜드 이름 없음** |
| 프로그램이 쓴 것 | 이미지 생성 API | 쉼표 나열식 |

대화형 도구에 API 용 프롬프트를 넣으면 그림이 안 나옵니다.
`logo for a brand called ...` 는 상표 정책에 걸려 거절당하고,
쉼표로 나열한 낱말 뭉치는 지시문으로 읽혀 되묻기만 합니다.

## 5. 보너스 과제 (선택)

명세는 두 가지 중 선택입니다. **"다국어 네이밍 지원" 을 택했습니다.**

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| **한글 + 영문 네이밍 동시 생성** | ✅ **선택함** | 후보마다 `name`·`english`·`reading` 세 가지 |
| 경쟁사 분석 → 차별화 포인트 제안 | ✅ 함께 구현 | 선택하지 않았지만 동작합니다 |

### 다국어 네이밍을 어떻게 만드는가

프롬프트(`MULTILINGUAL_RULE`)가 영문 표기의 조건을 못 박습니다.

- 소리 나는 대로 옮기거나(온기 → Ongi), 뜻이 통하는 영어 낱말로(쉼표 → Comma)
- **간판·도메인·SNS 계정에 그대로 쓸 수 있어야** 하므로 알파벳만, 12자 안쪽
- 영어권 사람이 발음하기 쉬울 것, 다른 뜻으로 읽히지 않을 것
- 후보끼리 영문 표기가 겹치지 않을 것

`reading` 에 읽는 법(`OWN-gee`)을 함께 받아, 영어권 사람에게 이름을 소개할 때 씁니다.

**검증합니다.** 영문 표기가 비었거나 알파벳이 아닌 글자가 섞이면
`run_report.md` 에 기록됩니다. 버리지는 않습니다 — 사람이 보고 판단할 문제입니다.

결과 문서에는 `쉼표 (Comma, COM-ma)` 형태로 실립니다.
