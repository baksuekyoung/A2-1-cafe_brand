# 팀장님 저장소로 옮기기

> 최종본은 **박수경 팀장님 개인 GitHub 저장소**입니다.
> 이 저장소는 팀원 결과를 모아 정리하는 **작업본**이고, 다 정리한 뒤 통째로 옮깁니다.

---

## 왜 파일만 복사하면 안 되나

압축해서 보내거나 파일만 복사해 올리면 **커밋 이력이 사라집니다.**
그러면 최종 저장소에는 "누가 언제 무엇을 했는지" 가 남지 않습니다.

가이드 체크리스트에 이런 항목이 있습니다.

> ✓ 최종 보고서에 **파트별 담당자와 주요 의사결정**이 정리되어 있는가

문서로도 적지만, **커밋 이력이 그 자체로 증거**입니다.
아래 방법을 쓰면 이력이 그대로 넘어갑니다.

---

## 준비 — 협업자 초대는 **팀원 전원**으로

팀장님께 이렇게 부탁드리면 됩니다.

1. 팀장님 저장소 페이지에서 **Settings** 클릭
2. 왼쪽 메뉴 **Collaborators** 클릭
3. **Add people** → 팀원 GitHub 아이디 입력 → 초대 (사람 수만큼 반복)

GitHub 개인 저장소는 **협업자 수 제한이 없습니다.** 같은 화면에서 이름만 바꿔 반복하면 됩니다.
초대 메일이 오면 각자 수락하면 끝입니다.

### 왜 한 사람이 아니라 전원인가

**각자 자기 이름으로 커밋이 남기 때문입니다.**

| | 전원 초대 | 한 사람만 초대 |
| --- | --- | --- |
| 커밋 작성자 | 각자 본인 이름 | 전부 그 한 사람 |
| "파트별 담당자" 증명 | **이력이 자동으로 증명** | 문서로만 |

가이드 체크리스트의 *파트별 담당자* 항목이 커밋 이력에 그대로 박힙니다.
표로 적는 것보다 확실한 증거입니다.

### 충돌 걱정은 하지 않아도 된다

여러 명이 같은 저장소에 올리면 보통 충돌이 나는데, 이 팀은 나지 않습니다.

```
[1] → step1_brief.py       각자 다른 파일만 건드린다
[2] → step2_naming.py
[3] → step3_palette.py
[4] → step4_logo.py
```

[`데이터-계약.md`](데이터-계약.md) 에서 **파일을 하나씩 나눠 둔 것이 여기서도 효과를 냅니다.**

### push 가 어려운 분이 있으면

초대는 받았는데 Git 이 낯설어 못 올리는 경우가 있습니다.
그때는 **파일만 보내 주시면 대신 커밋**하고, 커밋 메시지에 작성자를 적습니다.
(아래 "팀원 결과를 받을 때" 참고)

---

## 옮기기 — 상황에 따라 둘 중 하나

### ① 팀장님 저장소가 **비어 있을 때** (가장 깔끔)

저장소를 만들 때 README 도 `.gitignore` 도 체크하지 않은 상태입니다.

```bash
git remote add team https://github.com/<팀장계정>/<저장소이름>.git
git push team main
```

**이력이 통째로 그대로 갑니다.** 커밋 하나하나의 작성자와 날짜가 유지됩니다.

### ② 팀장님 저장소에 **이미 무언가 있을 때**

저장소를 만들면서 README 를 함께 만든 경우입니다. 두 이력을 먼저 합쳐야 합니다.

```bash
git remote add team https://github.com/<팀장계정>/<저장소이름>.git
git fetch team
git merge team/main --allow-unrelated-histories -m "merge: 팀장님 저장소와 합치기"
git push team main
```

`--allow-unrelated-histories` 는 "서로 남남이던 두 이력을 합친다" 는 뜻입니다.
없으면 Git 이 안전을 위해 거부합니다.

> **`git push --force` 는 쓰지 마세요.** 팀장님이 이미 올려 둔 것이 있으면 지워집니다.

## 옮긴 뒤 확인할 것

```bash
git log --oneline --graph | head -20      # 이력이 살아 있는지
git log --format="%an" | sort -u          # 작성자가 여럿인지
```

작성자 목록에 팀원 이름이 나오면 성공입니다.
한 사람만 나오면 파일만 복사된 것이니 다시 확인해야 합니다.

## 팀원 결과를 받을 때

각자 다른 방식으로 보내올 수 있습니다. **어느 쪽이든 커밋은 여기서 만듭니다.**

| 받는 방식 | 이력 |
| --- | --- |
| 팀원이 직접 이 저장소에 push | 작성자가 그대로 남습니다 (가장 좋음) |
| 카톡·메일로 파일을 보내옴 | 커밋 작성자가 노희선이 됩니다 |

두 번째 경우, **커밋 메시지에 누가 만든 것인지 적습니다.**

```
feat: [2] 네이밍·슬로건·스토리 (박연수 작성)

박연수님이 보내 주신 파일을 그대로 넣었습니다.
```

이렇게 하면 파일로 받았어도 기여가 이력에 남습니다.
